# Commit Notes: Rosetta Interface2 Filename Fix

Date: 2026-02-15
Base commit: `73588f8`
This commit 75790a5

## Summary
Fixes `interface_score` being `0` for all round2/refold structures when filenames contain embedded `.pdb__...` segments.

## Problem
- `rosetta_interface2` outputs used names like:
  - `...sample0_-1_2.pdb__sample0_-1_2.pdb`
- `src/pipeline/rosetta/get_interface_energy.py` built `rosetta_path` using:
  - `os.path.basename(x).split('.pdb')[0]`
- For names containing `.pdb__...`, this truncates too early and points to a non-existent Rosetta `.out` path.
- Missing `.out` then caused empty `binder_energy` (`{}`), and downstream `interface_score` became `0` for all rows.

## Code Changes

### `src/pipeline/rosetta/get_interface_energy.py`
- Added `_pdb_stem(path_str)` using `Path(...).stem`.
- Replaced fragile basename/split logic with stem-based naming for:
  - `pdbname`
  - `rosetta_path`
  - optional plot output name

## Rationale
- `Path(...).stem` preserves full logical IDs for files such as `foo.pdb__sample7_-1_3.pdb` (stem = `foo.pdb__sample7_-1_3`), matching job directory names generated by pipeline steps.
- Prevents systematic path mismatch and restores valid interface energy parsing for round2/refold outputs.

## Validation
- `python -m py_compile src/pipeline/rosetta/get_interface_energy.py` passed.
- Local stem sanity check confirmed expected behavior for:
  - `foo.pdb`
  - `foo.pdb__sample0_-1_2.pdb`

## Operational Note
- Existing completed runs with already-written `output/rosetta_interface2/interface_scores.csv` will still show stale zero values.
- Re-run `rosetta_interface2` and downstream ranking steps to regenerate corrected interface scores.
